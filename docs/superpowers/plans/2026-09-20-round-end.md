# 进程身份 = PID + 启动时刻；等待用 pidfd —— 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「这一轮结束了没有」从**猜**改成**问**。现在等的是「codex 从 `/proc` 消失」，而真正往日志里写字的是**包装器**——tee 循环读的是 codex 的 stdout **管道**，codex 的后代继承了同一个管道，codex 死了管道不 EOF。实测排干时间线：`t=0.000s codex=zombie writer=alive` → `t=2.987s codex=gone writer=alive` → `t=3.007s` 两者皆 gone。于是「续跑之前必须确认没有人还会往这份日志里写字」这件事，今天判的是另一个进程。改法三件：① 进程身份 = **PID + `/proc/<pid>/stat` 第 22 字段（启动时刻）**，成对存进元数据；② 等待用 `os.pidfd_open` + `select`，删掉轮询；③ 三个**命名 bool 谓词**代替三态裸字符串，让「僵尸算哪边」不再靠记忆。

**Architecture:** 身份分两次落盘。`run_codex` 是唯一的 spawn 入口，它在 **Popen 之前**把包装器身份（`os.getpid()`，此刻就知道）写进元数据，在 **Popen 之后**立刻补上 codex 身份——中途崩掉的失败面因此从「两个写者共写一份日志」降级成「这一轮发不了信号」。判定收敛成一个私有三态函数 `_process_state(pid, start)`（`alive`/`zombie`/`gone`），外面只看三个命名谓词：`codex_should_be_signaled`（僵尸不发）、`task_is_busy`（包装器 **或** codex 还活着）、`log_writer_finished`（包装器 `!= alive`，僵尸算写完）。等待是 `wait_for_writer_exit(meta, timeout)`：`pidfd_open` + `select`，pidfd 在**终止**那一刻就可读、不等父进程回收——「可读 == 停止运行 == 停止写日志」正是要问的那个谓词。`find_codex_pid`（扫 `/proc` 按 argv 比对）、`pid_alive`、`wait_for_exit` 三个函数连同两个轮询常量一起删除。

**Tech Stack:** Python 3 stdlib。`codex_agent.py` **加 `import select`、删 `import time`**（`time` 唯一的用户就是被删掉的那个轮询循环）；`test_codex_agent.py` 新增 `import ctypes`、`import inspect`。零第三方依赖。

```python
def _read_stat_fields(pid):
    """`/proc/<pid>/stat` 里的 `(运行状态, 启动时刻)`，都是 `str`；进程不在了返回 `None`。

    **整文件读 bytes，从最后一个 `)` 之后切。禁止按行读、禁止 split() 全文。**
    `comm` 是进程自己用 `prctl(PR_SET_NAME)` 设的**任意 15 字节**：空格、括号、
    制表符、**裸换行**全都进得去（2026-09-20 实测 comm=`a b)c\\td\\ne`，那时
    这个文件**按行读会得到 2 行**，而第一行里最后一个 `)` 落在 comm 内部）。
    按行读切出来的「启动时刻」是 comm 的碎片，整套身份比对当场瞎掉，
    而且它瞎得很安静——只在别人给进程改过名的时候才发作。

    `tail[0]` 是 stat 的第 3 字段（state），`tail[19]` 是第 22 字段（starttime）：
    前两个字段 pid 和 comm 已经被切掉了，所以下标是 `22 - 2 - 1`。
    """
    try:
        raw = pathlib.Path(f"/proc/{pid}/stat").read_bytes()
    except OSError:
        # 进程随时可能退出（ENOENT），/proc 也可能读到一半没了——一律当「不在了」
        return None
    tail = raw[raw.rindex(b")") + 2:].split()
    return tail[0].decode(), tail[19].decode()


def _identity_of(pid):
    """采集身份：`(str(pid), 启动时刻)`。**成对返回**，拿不到半截。

    半截身份等于退回裸 PID，而裸 PID 判不出僵尸也挡不住复用——那正是这轮要修的。

    **只在「这个进程此刻必然活着」的地方调**：`os.getpid()` 自己，和刚 `Popen`
    回来的子进程（哪怕它秒退也还是僵尸，`/proc/<pid>/stat` 照样在，直到 `proc.wait()`）。
    这条前提塌了就直接炸，不返回 `None` 让调用方去猜——猜出来的那个分支没人测得到。

    元数据里的身份**一律是 `str`**，这里是唯一的 int→str 落地点；
    还原成 int 只有 `os.pidfd_open` 和 `os.kill` 两处。
    """
    fields = _read_stat_fields(pid)
    if fields is None:
        raise RuntimeError(f"/proc/{pid}/stat 读不到，而这个 pid 本该此刻必然活着")
    return str(pid), fields[1]


# **PID 复用的余量是 445,255 倍，所以这里零行代码去防它。** 启动时刻的分辨率是
# 10ms（CLK_TCK=100），要让两副身份撞车就得在同一个 10ms 刻度内把同一个 PID 发两次，
# 而 PID 是顺序分配、绕完 pid_max 才回头：
#     pid_max 4,194,304 → 10ms 内绕完一圈需 4.19 亿次 fork/秒
#     本机实测 fork 速率 942 次/秒（绕一圈 1.2 小时）→ 余量 445,255 倍
# （审查用 PID namespace + 直接写 ns_last_pid 强制构造过撞车，那是实验室手法。）
# **唯一真实的边界**：别拿这套身份去判一个活不到 10ms 的短命进程。
# 本工具记身份的只有 codex 和包装器，都是分钟到小时量级。
def _process_state(pid, start):
    """这副身份现在处于哪一态：`"alive"` / `"zombie"` / `"gone"`。

    **私有。** 三态裸字符串不出这一段，外面只看下面三个命名谓词——僵尸在两处
    **语义相反**（codex 僵尸＝别发信号也别算写完；包装器僵尸＝已经写完了），
    把三态交给 6 个调用点，等于把这张映射表交给记忆。
    """
    if pid is None or start is None:
        # **不许吞成 gone。**「身份没记下来」和「进程没了」是两件事：前者是
        # 「这一轮还没 spawn 完」，吞了就会把它报成已结束，cmd_run 放行第二个 run。
        # 调用方必须自己先分开这两种（见 codex_should_be_signaled）。
        raise ValueError(f"身份不全：pid={pid!r} start={start!r}，"
                         f"「没记下来」不是一种进程状态，调用方必须自己先分开")
    fields = _read_stat_fields(pid)
    if fields is None:
        return "gone"
    state, start_now = fields
    if start_now != start:
        # 同一个 PID，但不是同一个进程——它被复用了。裸 PID 在这里会说「活着」。
        return "gone"
    return "zombie" if state == "Z" else "alive"
```
