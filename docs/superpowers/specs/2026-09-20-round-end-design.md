# 等的不是「codex 没了」，是「写日志的那个进程走了」

日期：2026-09-20　状态：按 spec 审查重写（第三版），待二轮审查

判据层级：**三条铁律 > 仓库规范 > 既有文档**。

## 版本小史（留着是因为两次否决各带一条判据）

- **v1 收尾标记**：包装器写一行「本轮到此为止」，等的人文本匹配。
  用户否：「拿给人读的日志当 IPC 信道，为了一个布尔值做文本匹配」。
- **v2 文件锁**：方向对，但把「净删减」当成正确性论据，而账**不平**（审查做账：持平偏加）。
  **用没核对过的账当论据，本身就是铁律 1 要拦的**。这一版先把账做平再说。

## 1. 病根（审查把它钉得比我更硬）

`interrupt-and-resume` 打断后等的是 codex 进程从 `/proc` 消失，而该等的是
**写日志的包装器走了**：tee 循环读的是 stdout **管道**，codex 的孙进程继承了它，
codex 死了管道不 EOF。

审查照 `run_codex` 结构复刻实测：

```
t≈0.5s  codex 状态=Z(僵尸) cmdline_len=0   日志锁=DENIED
t≈2.5s  codex 状态=Z       cmdline_len=0   日志锁=DENIED
TEE_EOF t=3.07s                            日志锁=ACQUIRED
```

**排干期间 codex 是僵尸、`/proc/<pid>/cmdline` 为空**，而 `find_codex_pid` 的第三道过滤
是 argv 元素精确比对 → 必然落空 → 现在的 `wait_for_exit` **秒返 True**。
**这个窗口不是概率事件，是结构上恒成立的。**

## 2. 修法：排他文件锁，加在日志文件本身

| 谁 | 做什么 |
|---|---|
| `run_codex`（唯一的长写者） | 开日志后立刻加排他锁，持到进程结束 |
| 下一轮的 `run_codex` | 拿同一把锁——**拿到才往下走**。等待就发生在这里 |

答案由**内核**给：正常退出、崩溃、`kill -9` 都释放（实测四行全部复现）。

### 必须 `flock`，不能 `fcntl.lockf`

实测：等的人**只读打开**去试 `lockf` 直接 `EBADF`；而且 `lockf` 同进程不互斥，
自己挡不住自己。**这条选型理由必须进注释**，否则下一个人按「POSIX 更现代」换掉会当场炸。

## 3. 没有 `wait_for_writer` 这个函数——等待折进 `run_codex`

审查指出：独立的 `wait_for_writer(log_path, ...)` 会和 `wait_for_exit(report_path, ...)`
成为一对**吃不同文件的兄弟函数**，传错的后果是**恒返 True**（没人锁报告）——静默、看起来
正确、永远错。而且返回值可以被忽略，忽略即回归今天的 bug。

**折进 `run_codex` 之后**：

- 调用方**不可能忘了等**——「不论有没有发过 INT 都要等」从靠记住变成结构保证；
- 路径由 `run_codex` 自己拥有，**传错文件在结构上不可能**；
- 「日志还不存在」自动消失（`"ab"` 会建）；
- 同进程双 fd 自锁在结构上不可能（实测：同进程第二个 fd 试 `flock` 会 DENIED）。

`cmd_interrupt_and_resume` 里 `wait_for_exit` 那一段整段删掉。
**代价要认**：阻塞前必须先 `print` 一行，否则等待的那几秒屏幕上一个字都没有
（这个毛病已登记在案，别让它变严重）。

## 4. 拿锁的位置：在 `write_meta` / `clear_report` **之前**

`run_codex` 自己写明的不变量是「校验排在 `write_meta`／`clear_report`／spawn **全部之前**：
任何一件先发生，失败就会留下半个状态」。拿锁是**会失败**的动作，所以必须排在那条线之前。

**这顺带堵死一个现存的并发 bug**（审查发现）：全新任务名的两个 `run` 同时起时，
`old_meta is None` → **根本不过 pid 闸** → 两个都 `write_meta`、都 `clear_report`、都开日志。
锁提到最前面之后，它是这条路上**唯一**的互斥闸。这是白送的收益，不是额外成本。

## 5. 拿不到锁：等到超时再拒，不立即拒

排干是**秒级、自愈**的（实测 3.07s）。立即拒会让 `cmd_run` 复用任务名、`cmd_resume` 紧跟
`stop` 这两条路在那几秒里被误拒——**把瞬态条件做成硬失败**。

所以：`LOCK_NB` + sleep 轮询到超时。拒绝语按 `kind` 分支说人话。

**「直接阻塞等」这条要撤掉**：`fcntl.flock` 没有 timeout 参数（实测），
要超时就还是轮询。v2 把「删掉轮询循环」写进净减法，是错的。

### 超时的真实职责

**不是「防内核抽风」**（内核不会让 `flock` 无故挂起）。它是**第 6 节那条前提塌掉时的
可观测失败**——触发时下一个人该去查的是「谁继承了日志 fd」。

常量改名 `ROUND_WRITER_EXIT_TIMEOUT`，锚点换成**本量纲**的实测值：
INT → 包装器放锁 **3.07s / 3.08s**（含孙进程排干），余量约 20 倍。
沿用旧的 `1.854s` 锚点会让那条常量测试和注释一起说假话。

## 6. 第 6 层前提：**日志 fd 不许被 codex 及其任何后代继承**

这是本版全部优势的唯一支点。实测：孙进程一旦继承日志 fd，**`kill -9` 之后锁依然被持**
——优势归零，而且退化得**比 v1 更坏**：v1 里包装器被硬杀只是「等到超时」这一种边角，
这里变成**正常路径**上每一轮都等到超时然后拒绝，且失败是静默的（锁还在、代码一切正常、答案错了）。

而今天这条前提由**两层默认值**保证，没有任何人显式承诺：

| 来源 | 性质 |
|---|---|
| PEP 446：`open()` 的 fd `inheritable=False` | 语言默认值 |
| `subprocess.Popen(close_fds=True)` | 库默认值 |

**违反仓库规范第 6 条「不要用默认缺省值」**，而且这是这类 bug 四层里**第一次把承重前提
完全托付给默认值**。触发方式都很日常：有人加 `pass_fds=` 给 codex 开旁路、有人调试时写
`close_fds=False`、有人把 `open()` 换成 `os.open()` 忘了 `O_CLOEXEC`。

**上闸（必须做，写注释不算）**：

1. 对日志 fd 显式 `os.set_inheritable(fd, False)`；`Popen` 上**显式写** `close_fds=True`。
   两行代码换掉两层默认值。
2. **一条红得出来的测试**：让持锁进程的孙进程**故意继承**日志 fd（`close_fds=False`），
   断言此时锁不释放。这条是给未来那个加 `pass_fds` 的人准备的。

## 7. 日志有两类写者，只有长写者持锁

| 写者 | 持锁吗 | 为什么 |
|---|---|---|
| `run_codex` 的 tee 循环 | **持** | 它就是「还会不会有人写」的那个人 |
| `interrupt_codex` 的打断痕迹 | **恒不持** | 它在 `forward_as_sigint` **信号处理器**里跑，而锁正被同一个进程持着 |

**「为了一致性也给它加锁」会死锁**，审查实测：信号处理器里自锁，`timeout` 发的 SIGTERM
重入同一个 handler 再次死锁，**SIGTERM 杀不掉，两分钟后才被强杀**，tee 循环再也收不了尾，
整轮上下文报废。

这条必须落成 `interrupt_codex` 旁边的注释。正确性不受损：它只在 `os.kill` 成功后才写，
而它写的那一轮必然正被它自己打断。

## 8. 读者恒不试锁

咨询锁挡不住不试锁的读者，实测 `status` 照读不误。**但要把这条写成约束**：
下一个人「为了安全」给 `read_round`/`read_last_round` 加 `flock`，`status` 就会被一轮
长任务挡上几小时。注释落在那两个函数旁边。

## 9. 前提：隔离目录必须在本地文件系统上

`flock` 在 NFS 上是用 POSIX 记录锁模拟的，`-o local_lock` 会退化成纯本地锁——
那时「另一台机器上的写者」完全看不见。`$HOME` 实测在 ext4 本地盘，当前无风险。
这条写在 `isolation_home` 旁边。

## 10. `find_codex_pid` 不动，但补第四条理由

它回答的是另一个问题（**要给哪个 pid 发信号** / **要不要发**），锁给不出 pid、也不说持有者是谁。
两者互补不冗余。

**要补的**：实测发现它今天答的其实是「codex 还活着**且还有 argv**」——排干期间 codex 是僵尸、
`cmdline` 为空，argv 过滤把它挡在外面。这是**想要的**（`os.kill` 对僵尸成功但无效，
真放进来会给一个收不到信号的进程写打断痕迹），但今天只是 argv 过滤的**副产品，不是写明的不变量**。
补成第四条理由，否则谁去「精简那三道过滤」就会打破它。

## 11. 实体账（这次先做平再写结论）

| | 删 | 加 |
|---|---|---|
| 函数 | `wait_for_exit`（含约 30 行 docstring） | — |
| 常量 | `INTERRUPT_EXIT_TIMEOUT` → 改名换锚点 | — |
| 调用点 | `cmd_interrupt_and_resume` 里那一段 | — |
| 依赖 | — | `import fcntl` |
| `run_codex` | — | flock 2 行 + `set_inheritable` 1 行 + 显式 `close_fds` + 按 `kind` 的拒绝语 |
| 测试 | `TestWaitForExit` 4 条 | 约 8 条 |

**是净减法**（函数少一个、调用点少一个、失败模式少一类），但**加了一条依赖和若干行**。
不拿这个当正确性论据——正确性由第 1 节的实测和第 6 节的上闸撑着。

## 12. 测试

| 测什么 | 关键点 |
|---|---|
| 还在写时拿不到 | 真持锁进程 → `run_codex` 在超时内拒绝 |
| 走了就拿得到 | 持锁进程退出 → 立即往下走 |
| **`kill -9` 也拿得到** | 硬杀持锁进程 → 往下走 |
| **孙进程继承日志 fd 时锁不释放** | 第 6 节的红测试，给未来加 `pass_fds` 的人 |
| **codex 早没了、包装器还在排干时必须继续等** | 本次回归锁。突变：换回等 PID → 必须红 |
| 拿锁在 `write_meta`/`clear_report` 之前 | 突变：挪到之后 → 必须红 |
| `interrupt_codex` 不持锁 | 突变：给它加锁 → 必须红（**用超时保护，别让测试自己挂死**）|
| 读者不试锁 | `status` 在一轮跑着时照常读 |
| 超时 | 锁一直被持 → 拒绝、退出码 2、消息说人话；等待期间 `os.kill` 零调用 |
| 常量锚点 | 绝对值 + 理由（3.08s × 约 20 倍）都钉住 |

依赖外部进程的测试**先断言前提成立**（本仓栽过七次）。

## 13. 非目标

- `judge`、`stop`、`read_*` 的判据一律不动。
- `cmd_resume` 的语义不变——但**要认**：它会多一条「等上一轮写者」的路径（v2 说「不动 resume」是假话）。
