# 进程身份 = PID + 启动时刻

日期：2026-09-20　状态：第四版（用户提出的方案），待审查

判据层级：**三条铁律 > 仓库规范 > 既有文档**。

## 版本小史（三次被否，每次都是因为我在绕）

| 版本 | 做法 | 否掉的理由 |
|---|---|---|
| v1 | 包装器往日志写一行「收尾标记」，等的人文本匹配 | 用户：拿给人读的日志当 IPC 信道，为了一个布尔值做文本匹配 |
| v2 | 日志文件加排他锁 | 审查：把没核对过的「净删减」当正确性论据；锁的位置错；「阻塞等」与「保留超时」矛盾 |
| v3 | 同上 + 修正 | 审查：**锁的释放挂在 stdout 管道上**，而 stdout 是刻意给全部后代的——病根被继承进了新答案；且拿锁必须提前 open 日志，`tell()` 快照过期，第二、三层的 bug 原样复活 |

**三版都在绕同一个东西**：我给自己立过一条「不存 PID」的规矩，理由是「PID 会过期、会被复用」。
那条理由对**裸 PID** 成立，我却把它当成了全面禁令，**从没问过有没有办法让存下来的 PID 不含糊**。

有：**`/proc/<pid>/stat` 的第 22 个字段是进程启动时刻**。PID + 启动时刻 = 唯一身份。
这是 systemd、docker 在用的标准做法。

## 1. 要解决的问题

`interrupt-and-resume` 打断当前轮之后，续跑之前必须确认**没有人还会往这份日志里写字**。
现在等的是「codex 从 `/proc` 消失」，而真正在写的是**包装器**：tee 循环读 codex 的 stdout
**管道**，codex 的后代继承了它，codex 死了管道不 EOF。实测：

```
codex 真正退出于  t=0.04s        （此后是僵尸，cmdline 为空）
tee 循环（管道 EOF）于 t=3.08s    （这期间日志还在长）
```

后果：续跑已经开始、新一轮的分隔符落了下去，上一轮的尾巴还在往后追——
上一轮丢自己的尾巴，新一轮背上一轮的错误行。

## 2. 修法

**进程身份写进元数据，判存活就是比对身份。**

```
codex_pid / codex_start      spawn 之后立刻记
writer_pid / writer_start    run_codex 自己的（就是那个在写日志的进程）
```

```
process_state(pid, start) -> "gone" | "zombie" | "alive"
```

读 `/proc/<pid>/stat`：文件不在 → `gone`；第 22 字段对不上 → **这是另一个进程**（PID 被复用）→ `gone`；
第 3 字段是 `Z` → `zombie`；否则 `alive`。

**解析要点**：`comm` 字段可能含空格和括号，必须从**最后一个 `)`** 之后切字段（实测名字含 `) ` 的进程照样读得对）。

### 三处用法

| 谁问 | 问什么 | 怎么答 |
|---|---|---|
| `cmd_stop` / `cmd_interrupt_and_resume` | codex 还在不在（要不要发信号） | `process_state(codex_pid, codex_start)` |
| `cmd_run` 查重 / `cmd_status` | 这个任务还在跑吗 | 同上 |
| **续跑之前** | **还有人往日志里写吗** | `process_state(writer_pid, writer_start)`，等到 `gone` |

### 僵尸从副产品变成显式判断

现在 `find_codex_pid` 用 argv 精确比对，而僵尸的 `cmdline` 为空 → 顺带被挡住。
那是**想要的行为**（对僵尸 `os.kill` 成功但无效），但它是副产品，不是写明的不变量——
谁去「精简那三道过滤」就会打破它。

换成读 state 字段之后，这件事变成**显式的一行**：僵尸不发信号、但也不算「写完了」
（它的父进程还在排干）。

## 3. 删掉什么

| 删 | 因为 |
|---|---|
| `find_codex_pid` 扫全 `/proc` + argv 元素精确比对 + `comm` 过滤 + `uid` 过滤（约 40 行 + 大段论证） | 身份直接存着，不用反查 |
| 「报告路径在 argv 里且按任务唯一」这条约定 | 不再依赖它 |
| 「刻意不存 pid」那条规矩及其论证 | 它防的是裸 PID，启动时刻已经把歧义消掉 |
| `wait_for_exit`（等错了对象） | 换成等 writer |
| v2/v3 整套文件锁：fd 继承前提、信号处理器死锁、`tell()` 快照过期、`flock`/`lockf` 选型、NFS 前提 | 一条都不需要 |

**加的只有**：元数据四个字段、一个 `process_state` 函数、`import` 无新增（`/proc` 用内建 open）。

## 4. 剩下那个真问题，要说清楚而不是藏起来

**后台进程占着 stdout 管道时，包装器会一直活着。**

这不是本方案的缺陷，是事实：那时包装器**确实**还可能往日志里写，等它是对的。
`_tee_until_exit` 的注释里已经登记了这个现象（直接子进程 0.03s 退、tee 挂到 4.16s）。

本方案相对旧做法的进步在于**说得清**：超时时能明确告诉调用方

> codex 已退出（僵尸/已回收），但包装器还在读输出——很可能是它起的后台进程还占着输出管道。

而不是一个说不清成因的超时。三种成因分开说：

| 成因 | 怎么判 | 说什么 |
|---|---|---|
| 正常排干 | writer `alive`、codex `zombie`/`gone` | 等几秒就好 |
| 同名任务真的在跑 | codex `alive` | 换个任务名，或先 stop |
| 后代占着管道 | 超时后 writer 仍 `alive`、codex 早 `gone` | 上面那句话 |

## 5. 超时

保留轮询 + 超时（等的是别的进程，没有内核唤醒机制）。
锚点用**本量纲**实测：INT → 包装器退出 **3.07s / 3.08s**（含排干）。
常量改名 `WRITER_EXIT_TIMEOUT`，余量写实测倍数，别写一个凑不上的整数。

## 6. 测试

| 测什么 | 关键点 |
|---|---|
| 身份比对挡得住 PID 复用 | 构造「PID 相同、启动时刻不同」→ 必须判 `gone` |
| 僵尸判得出 | 真造一个僵尸（子进程退出、父进程不 wait）→ `zombie` |
| `comm` 含空格括号 | 名字含 `) ` 的进程 → 仍解析正确 |
| **codex 早没了、包装器还在排干时必须继续等** | 本次回归锁。突变：换回只看 codex → 必须红 |
| 三种成因各自的拒绝语 | 按 §4 那张表逐条 |
| 超时 | 等待期间 `os.kill` 零调用 |
| 常量锚点 | 绝对值 + 倍数都钉住 |

依赖外部进程的测试**先断言前提成立**（本仓栽过七次）。
