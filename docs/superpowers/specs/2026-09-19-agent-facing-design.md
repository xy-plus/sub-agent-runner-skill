# 交给其他 agent 用：`--skill` 白名单与机器可读的 `status`

日期：2026-09-19　状态：待审查

**判据层级**（用户明确，最高指示）：三条铁律 > 仓库规范 > 既有文档（都是证据，不是权威）。

## 1. 为什么现在做这件事

用户说：「做完之后，我就要拿给其他的 Agent 去用了。」

这句话把一类原本可以容忍的问题变成了不能容忍的：**人会看提示、会发现自己写错了；agent 不会。**
人手抖把 skill 路径写错，看一眼输出就知道 codex 没读到；agent 拿到 exit 0 就往下走。

按这个判据扫一遍现状，有两处**对人尚可、对 agent 致命**：

| 现状 | 人 | agent |
|---|---|---|
| 「要传 skill 就在 brief 里写绝对路径」是**文档约定** | 写错了自己看得出来 | **静默失效**：codex 读不到那个文件，照样跑完、照样 exit 0 |
| `status` 用空格对齐输出，而 `reason` 里**就有空格** | 一眼能读 | **切不开**：无法可靠地取出 state 这一列 |

两处都不是「不好看」，是**工具在无声地骗调用方**——和上一轮修掉的三处同一性质。

## 2. 改动 A：`--skill` 白名单进 CLI

### 现状的病根

「传 skill 用绝对路径写进 brief」这条知识，现在住在 `SKILL.md` 的一行表格里。它有三个问题：

1. **路径写错静默失效**——没有任何一方校验那个文件存在。
2. **允许集不可见**——埋在 brief 正文里，argv 里看不到、元数据里没有、事后审计不了。
3. **兜底句是人手写的**——工具自动前置的是「不得使用任何 skill」，而调用方要传 skill 时得自己在 brief 里破这个例，两句话谁覆盖谁没有定义。

### 契约

```
--skill <绝对路径>     可重复
--no-skill             与 --skill 互斥，二选一必填
```

三条带 prompt 的命令（`run` / `resume` / `interrupt-and-resume`）都收——**白名单是每一轮的事，不是任务的事**：这一轮要它照 TDD 做，下一轮可能不用。

**二选一必填**（用户拍板）：与 `--effort`、`--account` 同待遇，不设缺省。理由是铁律 6——
而且这里「忘了写」的两种后果并不对称：默认成空白名单只会让 codex 少一个 skill（干活慢一点），
默认成「沿用上一轮」才是危险的。但即便安全方向的缺省也不设，因为**「这一轮给不给 skill」
本来就是调用方每次都该想一遍的事**。

### 工具负责什么

| 职责 | 细节 |
|---|---|
| 校验 | 每个路径必须是**绝对路径**且**文件存在**，否则拒跑（退出码 2）。路径写错从「静默失效」变成「当场报错」 |
| 派生兜底句 | 没给 `--skill` → 「不得使用任何 skill。」；给了 → 「不得使用任何 skill，除了以下这些：<逐个绝对路径>」。**调用方不再手写这句话** |
| 落进元数据 | `skills: [...]`，`status` 能看到这一轮给了什么，事后可审计 |

### 刻意不做：不把 skill 软链进隔离目录

软链进 `$CODEX_HOME/skills/` 会让 codex 把它当成**自己随时可取用的能力**，何时用由它决定。
而隔离目录存在的全部理由，就是防止 codex 因为看见了流程类 skill 就想去编排
（用户原话：本来是工作子代理，结果还要进一步创建子代理）。

传路径 + 那句话，skill 才是 **brief 调用的指令**，何时用由 brief 决定。
**这不是「结构化程度低」的妥协，这是正确的那一边。**

附带代价也真实：软链方案要求隔离目录从「每账号一个」变成「每任务一个」，否则并行任务互相污染。

### 实测背景（2026-09-19，codex 0.154.0）

- 隔离**有效**：主目录的 23 个 skill、2 个 MCP、3 个 hook，在隔离环境里**一个都没出现**。
- 隔离**有上限**：服务端自带 5 个 skill（`imagegen`/`openai-docs`/`plugin-creator`/`skill-creator`/`skill-installer`）
  始终可见，`CODEX_HOME` 结构上够不着。**这 5 个与「想去编排」无关，刻意不管它们**
  （关它们是在解决一个不存在的问题）。
- `~/.agents/skills/` 是 `CODEX_HOME` 管不到的共享扫描根：放了哨兵进去，codex **确实列出了它**。
  所以 `ensure_isolation` 对它非空即拒跑这条是承重的。
- **递归的能力关不掉**：`collaboration.spawn_agent` 等六个工具恒在，`--disable multi_agent`
  实测**无效**（加与不加，codex 报的工具清单逐字相同）。所以隔离挡的是**动机**不是**能力**——
  这条要写进注释，否则下一个人还会去试那个 flag。

## 3. 改动 B：`status` 输出改成制表符分隔的固定列

### 病根

现在用 `f"{task:<24} "` 这类空格对齐，而 `reason` 字段本身含空格（「报告缺失或为空＝没正常收尾」）。
**机器无法可靠切列。**

### 为什么不加 `--json`

加 `--json` 等于同一份事实有**两种呈现**，两边要永远保持一致——这正是这个仓库一路在消灭的东西
（「每条事实只有一个家」）。而制表符分隔是**零成本**的：一份输出，人照样读，`awk -F'\t'` 也能读。

### 格式

```
<任务名>\t<账号>\t<状态>\t<退出码>\t<工作目录>\t<reason>
```

明细行（错误行、报告预览）**保持缩进**，从而与数据行结构性可分（首字符是空白）。

退出码单独成列，因为它才是 agent 真正该读的那一位（`SKILL.md` 已写明「看数字，不看词」）。

## 4. 同时要内化的一条知识

`collaboration.spawn_agent` 恒在、`--disable multi_agent` 无效（实测 A/C 两个探针输出逐字相同）、
`skip_host_skill_discovery` 不影响服务端那 5 个。**隔离挡的是动机不是能力。**

落点：`ensure_isolation` 的 docstring 附近——那里现在只说「防自激活」，说得太模糊，
下一个人既不知道它在挡什么具体的东西，也不知道哪条路已经试过了。

## 5. 测试

| 测什么 | 关键点 |
|---|---|
| `--skill` / `--no-skill` 二选一必填 | 都不给 → 拒；都给 → 拒；三条命令各验一遍 |
| 路径校验 | 相对路径 → 拒；文件不存在 → 拒；**错误信息要点名是哪一个路径** |
| 兜底句派生 | 无 skill 与有 skill 两种措辞各钉一条；**断言的是真正送进 codex argv 的那段文本**，不是中间函数的返回值 |
| 元数据 | 落盘的 `skills` 与传入一致；`REQUIRED_META_KEYS` 同步 |
| `status` 分列 | 用 `split("\t")` 断言列数与各列内容；**reason 含空格时仍然切得开**（这是本改动的理由，必须钉死） |
| 明细行可分 | 明细行首字符是空白，数据行不是 |
| 突变复验 | 去掉路径存在校验、去掉互斥、把 `\t` 改回空格——逐个必须红 |

依赖外部文件的测试**先断言前提成立**。凡「断言常量等于那个常量自己」一律视为空测试——本仓栽过五次。

## 6. 非目标

- 不加 `--json`（见 §3）。
- 不关服务端那 5 个 skill（与递归问题无关，关它们是解决不存在的问题）。
- 不动 `wait_for_exit` 把「codex 没了」当「日志安静了」那条（已登记为独立跟进项）。
