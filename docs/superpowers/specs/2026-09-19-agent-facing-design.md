# 交给其他 agent 用：`--skill` 白名单与可切分的 `status`

日期：2026-09-19　状态：按 spec 审查重写，待二轮审查

**判据层级**（用户明确，最高指示）：三条铁律 > 仓库规范 > 既有文档（都是证据，不是权威）。

## 1. 为什么现在做这件事

用户说：「做完之后，我就要拿给其他的 Agent 去用了。」

这句话把一类原本可以容忍的问题变成了不能容忍的：**人会看提示、会发现自己写错了；agent 不会。**

### 实测：skill 路径写错，工具报「成功」而 codex 一件事没干

2026-09-19 真跑（`--effort low`，brief 指向一个不存在的 SKILL.md）：

| 阶段 | 实际发生 |
|---|---|
| codex 第一步 | `cat <路径>` → `exited 1: No such file or directory` |
| 第二步 | `find` 真实 home 找它 → **跑了 34.9 秒** |
| codex 结论 | 「未找到该文件，**因此无法严格按其流程执行，尚未创建 out.txt**」 |
| 磁盘 | `out.txt` **不存在** |
| 工具判定 | `success —— 正常收尾，本轮日志无未分类错误` |
| **退出码** | **0** |

**「零工作量」被报成「完成」。**没有任何别的信号能救：`cat` 的失败是 shell 退出码，
不匹配 `runtime_error_lines` 的三种错误形式，`judge` 结构上看不见它。

### 实测：`status` 的列表形态机器切不开

`cmd_status` 现在是 `f"{task:<24} {account:<8} {state:<8} {reason}  {dir}"`，
而 `reason` 含空格——**例子要举对**（计划作者指出初稿举错了：「报告缺失或为空＝没正常收尾」
其实不含空格）。7 个 `Verdict` 构造点里真正含空格的是另外 5 个，例如
「本轮被 INT 打断，上下文保留——接着 resume 即可，不用重跑」。结论不变，
但**照错例子写的测试测不到任何东西**。

**范围要说准**（初稿把它放大了）：单任务查询**今天就不用解析**——`status <任务名>` 的
退出码就是结论；`dir`/`account`/`effort`/`session_id` 也早就在 `tasks/<task>.json` 里。
**真正缺的只有一样：列表形态下每行的 state。**

## 2. 改动 A：`--skill` 白名单进 CLI

### 契约

```
--skill <SKILL.md 的绝对路径>    可重复
--no-skill                        与 --skill 互斥，二选一必填
```

三条带 prompt 的命令（`run` / `resume` / `interrupt-and-resume`）都收——
**白名单是每一轮的事，不是任务的事**。

`--skill` 指向的是 **SKILL.md 文件本身**，不是 skill 目录。错误信息要点名路径并说清期望
（实测传目录时 `is_file()` 为 False 会被拒，但调用方看不出为什么）。

### 校验：三条缺一不可

```
p.is_absolute() and p.is_file() and os.access(p, os.R_OK)
```

第三条是审查实测逼出来的：**权限 000 的文件 `is_file()` 返回 True，而 codex 的 `cat` 退 1**
——只查前两条的话，这次改动的核心承诺（路径写错从静默失效变当场报错）在「文件不可读」
这一支上原样漏掉。三条各钉一条测试。

另外拒绝路径中的**任何控制字符**（`\t`/`\n` 等）——理由见 §3。

### 兜底句由工具派生，调用方不许自己写

现有常量是 `SKILL_GUARD = "**不得使用任何 skill，除非本 brief 明确指定。**"`。
那半句「除非本 brief 明确指定」**本来就是「CLI 没有这个参数」的变通**：调用方无处声明白名单，
只好让 brief 正文去破例。

**`--skill` 出现之后，那半句就该消失**——白名单由 CLI 指定，brief 正文不再是声明渠道：

| 情况 | 工具前置的句子 |
|---|---|
| `--no-skill` | 「不得使用任何 skill。」 |
| 给了 `--skill` | 「不得使用任何 skill，以下几个除外：」+ 逐行绝对路径 |

**调用方的 brief 里若已含兜底句，直接拒跑**（退出码 2，提示改用 `--skill`/`--no-skill`），
而且这条检查**必须前移到 `check_can_resume`**，不能留在 `prepend_skill_guard` 里——
否则 `interrupt-and-resume` 会先发 INT、截断当前轮，再因为一个**本可提前发现**的理由拒绝。

这里要精化一下既有的那条判据。`check_can_resume` 的注释写的是「不可恢复的挪前面、可恢复的留后面」，
而按字面这条检查属「可恢复」（上下文还在）、可以留后面。**但那条判据的本意是
「有些检查在动手之前做不了」（比如 `ensure_isolation` 要先解析出账号）**，不是「可恢复就随便放」。

更准的说法：**凡是对「调用方已经交给我们的输入」的纯检查，一律在任何不可逆动作之前做完。**
brief 的内容就是这样的输入——白白烧掉一轮，即使可恢复也是浪费。

检测用**子串**匹配（认一个稳定词干），这是对「本仓刚把轮次边界从子串改成整行」那条教训的
**刻意例外**，必须在注释里说清楚：那次要从混杂文本里**解析自己的标记**，误判会让判据说谎；
这次要认的是**调用方写了任意措辞的兜底句**，误判的后果是拒绝一个确实在谈 skill 禁令的 brief
——而那**正是我们要拒的**。失败方向是良性的。
理由是铁律 2：这句话由工具拥有，两句并存时的优先级**根本不该需要被定义**。

这同时解掉了现有 `prepend_skill_guard` 的幂等闸——它靠 `startswith(SKILL_GUARD)` 去重，
而句子一旦每轮派生，这个判断就不成立；而 SKILL.md 把那句话明文写着，
调用方照抄进 brief 开头是**可达路径**，不拒就会出现两句互相矛盾的兜底句。
**拒绝比去重少一个分支，且把「无定义」变成「不可能」。**

### 元数据

`skills: [...]` 进元数据，与 `effort`/`started_at` **并列刷新**——沿用既有原则
「元数据描述的是**最后一次调用**」，不让实现者自己发明 resume 时用哪一轮的。

`REQUIRED_META_KEYS` 同步。**升级时机约束**：`_load_meta` 对缺字段的老元数据会拒绝并提示
「删掉它重新 run」——那会丢掉会话。实测目前三个隔离目录的 `tasks/` 全空（0 个 json），
所以现实影响为零，**但升级前必须确认没有在跑的任务**。

**拒绝半径比「那一个任务」大**：`all_metas()` 逐个走 `_load_meta`，所以**一个**缺
`skills` 的旧 json 会让 `status` 的列表形态整条退 2、一个任务都列不出来
（`find_meta` 同理，它也扫全部账号）。这不是新引入的行为——既有的六个字段本来就这样，
但升级窗口正好把它放大成「全部任务一起够不着」。这也正是「升级前确认 tasks/ 全空」
这条前置条件承重的原因。

### 刻意不软链进隔离目录（理由已按审查更正）

初稿的理由是「codex 看见流程类 skill 就想去编排」——**审查指出这条对精选集不成立**：
只软链 `test-driven-development` 时，codex 够不着 `subagent-driven-development`，那个口子打不开。
**留着一条错理由比没有理由更危险**，下一个人会拿它去推别的结论。

真正承重的是另外两条：

1. **可观测性**（更重要）：路径在 brief 里，「codex 到底读没读」**在日志里看得见**
   ——上面那个实验里就是 `cat <路径>` 那一行。软链成能力之后，用没用由它决定、**不可观测**。
   对一个主张「不骗调用方」的工具，这条是决定性的。
2. **奥卡姆**：软链要求隔离目录从「每账号一个」变成「每任务一个」，
   `isolation_home`/`find_meta`/`account_choices`/`ensure_isolation` 全线要改，换来的保证是零。

### `--no-skill` 必填的理由（已按审查更正）

初稿写「默认成空白名单只会让 codex 少一个 skill（干活慢一点）」——**那等于承认省略是良性的，
恰好论证了不必强制**。论据和结论打架。

站得住的理由：**这个工具要交给其他 agent 用。** 省略时分不清「调用方决定不给」和
「调用方根本不知道有这个参数」。强制显式把「没想过」变成 exit 2 当场报错。
代价很小：拒绝是**即时且完全可恢复**的（加个参数重跑，零损失），不像 `--effort`/`--account`
写错要花钱才发现。

### 这个改动关掉的是一个实例，不是一整类

`--skill` 堵住「路径写错」。它**堵不住**上面实验暴露的那一类：
codex 读完 skill 之后**拒绝执行**、只写一句「我没做」，`judge` 照样判 success。
那是判据层的问题（产物存在性由 brief 的 DoD 定义，工具层看不见），**另案**。

## 3. 改动 B：`status` 把 `reason` 挪到最后，用 `split(maxsplit=4)` 切

### 初稿的制表符方案被实测否掉

初稿说「制表符零成本，人照样读」——**假的**。按 tabstop=8 实测四行 status 输出的各列屏幕起始列：
`[0,16,24,32,40,80]` / `[0,16,24,32,40,88]` / `[0,8,16,24,32,40]` / `[0,32,40,56,64,80]`
——**四行没有一列对齐**，而现状空格定宽是稳定的 `[0,25,34,43]`。

### 采纳的方案：换列序，不换格式

```
<任务名>  <账号>  <状态>  <退出码>  <工作目录及其后的 reason>
                                     ↑ split(maxsplit=4) 在这里停
```

前四列**必须无空格**——但其中一列今天并不保证，要一并补上：

| 列 | 无空格由谁保证 |
|---|---|
| 任务名 | `_TASK_NAME` 正则，已有 |
| **账号** | **今天没人保证**：`account_choices()` 扫的是 `~/.codex-accounts/` 下的**任意目录名**，
建一个 `bad acct` 就进得了 `choices`（计划作者实测）→ 第二列当场冲垮 |
| 状态 | 五态枚举，已有 |
| 退出码 | 整数，已有 |

所以 `account_choices()` 要**拒绝含空白或控制字符的账号目录名**，并在错误信息里点名是哪个目录。
这和任务名限字符集是同一条理由：这个值会进入按空白切分的输出，**约束必须在入口**。

补齐之后 `line.split(maxsplit=4)` 才精确切出前四列，第五段是「dir + reason」。

**零新格式、人读体验一点不退化、少一个改动点。** 代价是 `dir` 与 `reason` 不可分——
可以接受：`dir` 已经在 `tasks/<task>.json` 里，而调用方真正要的是 state 和退出码。

退出码单独成列。它与 state 是同一份事实的两种编码，但**同源派生**（都来自 `EXIT[state]`），
不存在漂移风险——人读词、机器读码。

### 明细行

错误行与报告预览**保持缩进**，从而与数据行结构性可分（首字符是空白）。

### 控制字符必须在入口就挡住

审查实测：**`--dir` 可以含制表符和换行**（`mkdir`/`resolve()`/`is_dir()` 全过）。
一个换行就让「一行一任务」不成立，任何切分方案都救不回来。

所以 `--dir` 和 `--skill` 在解析时**拒绝任何控制字符**。这是把约束写进代码，
而不是指望「一般没人这么干」。

另外：`reason` 当前恰好不含制表符和换行（穷举 `Verdict(...)` 的 7 个构造点确认），
但这是**碰巧成立、无人守卫**——打印前对每个字段断言无控制字符，让「能切开」成为代码保证。

### `skills` 不进 status 的列

初稿 §2 说「`status` 能看到这一轮给了什么」，而 §3 的列清单里没有它——自相矛盾。
**定为不进列**：skill 路径是任意长度的绝对路径，进数据行会把格式撑坏；
要审计就读 `tasks/<task>.json`，那本来就是结构化的。

## 4. 要内化的一条知识

`collaboration.spawn_agent` 等六个工具**恒在**，`--disable multi_agent` 实测**无效**
（加与不加，codex 报的工具清单逐字相同）；`skip_host_skill_discovery` 不影响服务端那 5 个 skill。
**隔离挡的是动机，不是能力。**

落点：`ensure_isolation` 的 docstring 附近——那里现在只说「防自激活」，
既没说在挡什么具体的东西，也没说哪条路已经试过了。

（顺带记下审查复核过的三条实测：主目录 23 skills / 2 MCP / 3 hooks 全被挡住；
`~/.agents/skills` 放哨兵确实被 codex 列出来，所以那条非空即拒跑是承重的；
服务端 5 个 skill 逐字吻合且与「想去编排」无关，**刻意不管**。）

## 5. 测试

| 测什么 | 关键点 |
|---|---|
| `--skill`/`--no-skill` 二选一必填 | 都不给 → 拒；都给 → 拒；三条命令各验一遍 |
| 路径校验三条 | 相对路径 / 不存在 / **权限 000 不可读**，各一条；错误信息点名是哪个路径 |
| 控制字符 | `--dir` 和 `--skill` 含 `\t`、`\n` → 拒 |
| 兜底句派生 | 无 skill 与有 skill 两种措辞各一条；**断言的是真正送进 codex argv 的那段文本** |
| brief 自带兜底句 → 拒跑 | 含既有 `SKILL_GUARD` 的 brief 必须被拒，提示改用 `--skill`/`--no-skill` |
| 元数据 | 落盘 `skills` 与传入一致；resume 刷新；`REQUIRED_META_KEYS` 同步 |
| `status` 可切分 | `split(maxsplit=4)` 取出四列；**reason 含空格时仍切得开**（这是本改动的理由，必须钉死）；dir 含空格时也切得开 |
| 明细行可分 | 明细行首字符是空白，数据行不是 |
| 打印前的控制字符断言 | 构造一个含 `\t` 的 reason → 必须被挡住 |
| **既有测试迁移** | `test_codex_agent.py:799-801`（幂等）、`:1717`、`:1727`（argv 级 `startswith(SKILL_GUARD)`）三条会红，改成新语义 |
| 突变复验 | 去掉可读性校验、去掉互斥、去掉控制字符拒绝、把 reason 挪回中间——逐个必须红 |

依赖外部文件的测试**先断言前提成立**。凡「断言常量等于那个常量自己」一律视为空测试——本仓栽过五次。

## 6. SKILL.md 的改动（四者对齐）

| 现在写的 | 改成 |
|---|---|
| 「给它 skill：在 brief 里写该 skill 的**绝对路径**让 codex 自己读」 | `--skill <SKILL.md 绝对路径>`，可重复；不给就 `--no-skill`。**路径写错当场拒跑** |
| 「brief：……工具会自动前置「不得使用任何 skill」并打印一行提示」 | 兜底句由 `--skill`/`--no-skill` 派生，**不要自己在 brief 里写** |
| （没写）`status` 列表形态的行结构 | 补一句：**一行一个任务**、前四列是任务名／账号／状态／退出码、**缩进的行是明细不是任务**。这是**接口事实**不是机制泄漏（怎么切由调用方自己决定，不写 `split`），所以要正面钉死具体内容——照退出码表那样，否则整段删掉照样全绿 |

**注意泄漏测试**：兜底句一旦由工具派生，SKILL.md 复述其措辞就成了
`TestSkillDocDoesNotRepeatCode` 判据下的泄漏——只写「工具会派生」，不复述句子内容。

## 7. 非目标

- 不加 `--json`（同一份事实两种呈现，要永远保持一致——正是本仓一路在消灭的东西）。
- 不关服务端那 5 个 skill（与递归问题无关，关它们是解决不存在的问题）。
- 不修「codex 读了 skill 却拒绝执行、judge 照样判 success」那一类（判据层，另案）。
- 不动 `wait_for_exit` 把「codex 没了」当「日志安静了」（已登记为独立跟进项）。
